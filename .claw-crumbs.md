## Infra / data
- **Supabase** (project ref `jpzkscgwupdkbhlauqmf`): `applicants` table (full record in
  `jsonb data`) + Storage buckets `forms`/`photos`. Seed uses fixed UUIDs (idempotent).
  `supabase/schema.sql` + `scripts/setup-supabase.mjs` provision it.
- **Server store:** `lib/supabase.ts` (service-role, `server-only`) — never import into a
  client component.
- **Env vars** (Vercel prod scope + local `.env.local`, gitignored, never synced to Z:):
  `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (the `sb_secret_…` key, NOT publishable),
  `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `OPENAI_API_KEY`.
- **Prod-login HARD gotcha (2026-06-08):** the two `NEXT_PUBLIC_*` Supabase vars are
  **inlined into the browser bundle at BUILD time** — they must exist in Vercel **Production**
  scope and any change needs a **fresh redeploy** (`--force` / uncheck build cache) to take.
  Missing → `createBrowserSupabase()` throws "not configured" → login shows generic
  "Something went wrong". Symptom-2: `signInWithPassword` → `TypeError: Failed to execute
  'fetch': Invalid value` means a **malformed header value** — caused here by pasting the
  anon key from the Supabase dashboard **with the trailing newline + "This key is safe…"
  caption text** appended; the `Authorization: Bearer <key>\nThis key…` header is illegal.
  Fix: env value must be the bare JWT only. Verify a deploy by curling the live bundle and
  grepping for `jpzkscgwupdkbhlauqmf.supabase.co` + a clean anon JWT (no trailing chars).
- **Auth:** invite-only Supabase Auth. `role` + `applicant_id` in `app_metadata`
  (service-role only). Admin invites / password-reset / delete from `/admin`.
- **Email:** Supabase custom SMTP via **Resend** (configured in the Supabase **dashboard**,
  not the repo). `smtp.resend.com:465`, sender `noreply@menehune.io`. **SMTP Username MUST
  be the literal word `resend`** (password = API key) — an email-address username caused the
  502 invite failures. Branded templates in `supabase/email-templates/` are pasted into the
  dashboard; button links use `{{ .RedirectTo }}&token_hash={{ .TokenHash }}&type=invite|recovery`
  (NOT `ConfirmationURL`). Each sending origin must be in Auth → URL Config → Redirect URLs.

## Standing rules (cause real bugs if forgotten)
- **Real PII discipline:** `CMOP_Process.xlsx` = 44 real people. Analysis only — never parse
  names/emails/phones into git, a committed seed, or `.data/`. Real ID PDFs/scans contain a
  real SSN — gitignored; never sync/commit.
- Fill the **original VA AcroForm PDFs** via `pdf-lib` (lowest rejection risk); keep
  prefilled contract fields; leave signature/date blank for wet-signing.
- **Packet download gating:** `packetDownloadable` requires every form uploaded **+ stored**
  (real bytes on disk) **+ 100% + zero issues**, AND status REVIEWED. The displayed `%`
  (`packetCompleteness`) ignores `stored`/issues — so a packet can read **100% yet not be
  downloadable**. Seed candidates are 100% but never `stored` → no Download button until a
  real upload. Test helper: `node .qa-build/make-downloadable.mjs <applicantId>`.

## HR Command Center (`/hr`) — second app in this repo
- **What:** internal HR tooling for the three manual time sinks, across ALL contracts
  (CMOP is one of several, each with its own code/positions/rates): **New Hire Sync**
  (enter once → ordered copy panels + import CSVs for Paycor AND Employee Navigator),
  **Letter Studio** (offer/increase letters, single or batch-pasted from Excel → print
  or Word), **Payroll Bridge** (Unanet export → flags duplicates, unsplit OT, unmapped
  pay codes, unmatched employees, negative lines → clean Paycor import CSV).
- **Prototype:** 100% client-side, seed data in `localStorage`, no backend and no env
  vars. "Reset demo data" in the sidebar restores the seed.
- **Two deployables from one source:** the main app serves `/hr` alongside the CMOP
  packet app; `apps/hr-demo/` is a standalone Next app serving ONLY `/hr` (no Supabase
  needed). `app/hr/**` + `lib/hr/**` are COPIED into it by `scripts/sync-hr-demo.mjs`.
  Edit the originals, then re-run the script — `--check` exits 1 on drift and runs in
  CI (`.github/workflows/hr-demo-sync.yml`).
- **The one env-specific value** is `lib/hr/links.ts`: where "Candidate Packets" links
  point. Defaults to the internal `/admin`; the standalone sets `NEXT_PUBLIC_PACKETS_URL`.
  That indirection is what lets the sources be copied verbatim.
